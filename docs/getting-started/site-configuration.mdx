上一页已经启动模板。本页以 “Acme SDK” 为例，在保留模板使用手册的同时新增“产品指
南”大章节。这样每一步都能运行测试和预览；等自己的内容迁移完成后，再一起删除不需
要的模板手册及其导航。

## 配置文件 {id="locations"}

先了解每个文件负责什么：

| 文件                          | 作用                                   |
| ----------------------------- | -------------------------------------- |
| `meta/site.json`              | 站点身份、顶部大章节、导航和页脚       |
| `meta/sidebars.json`          | 每个大章节的左侧分组、小页面和阅读顺序 |
| `meta/type-annotations.json`  | 把 MDX 类型标注链接到参考页面          |
| `public/manifest.webmanifest` | 安装到桌面时的名称、显示方式和主题色   |
| `pages/index.tsx`             | 首页标题、说明和入口卡片               |

最常修改的是前两个 JSON 文件。类型映射会在
[MDX 组件](/writing/mdx-components#type-annotations) 中用实际效果解释，首页和
manifest 则放到下一页 [外观定制](/getting-started/appearance)。

## 字段参考 {id="fields"}

`meta/site.json` 的字段及实际用途如下：

| 字段          | 作用                                 | 示例                     |
| ------------- | ------------------------------------ | ------------------------ |
| `title`       | 浏览器标题、站点名称和页面元信息     | `"Acme SDK"`             |
| `description` | SEO 与分享摘要                       | `"Acme SDK 中文文档"`    |
| `slogan`      | 首页浏览器标题中的短标语             | `"Build with Acme"`      |
| `company`     | 左上角和页脚中的组织名称             | `"Acme"`                 |
| `companyUrl`  | 页脚组织链接以及外部链接识别         | `"https://acme.example"` |
| `repo`        | 源码链接使用的 GitHub `owner/repo`   | `"acme/sdk-docs"`        |
| `theme`       | 浏览器 UI 的十六进制主题色           | `"#0a8f6a"`              |
| `sections`    | 大章节 id、标题和页面主题名称        | 见完整示例               |
| `navigation`  | 右上角链接，可以是站内章节或外部页面 | 见完整示例               |
| `footer`      | 页脚链接分组                         | 见完整示例               |

`sections[].theme` 与根级 `theme` 含义不同：

```json
{
  "theme": "#0a8f6a",
  "sections": [{ "id": "guide", "title": "指南", "theme": "green" }]
}
```

- 根级 `theme` 是浏览器使用的颜色值。
- `sections[].theme` 是模板内置样式名，可选 `blue`、`green`、`purple`、
  `nightly` 或 `legacy`。

预期结果是打开 `guide` 页面时使用绿色章节样式，而浏览器地址栏或安装后的页面 UI
使用 `#0a8f6a`。

## 配置关系 {id="relationships"}

同一个大章节 id 会出现在三个配置位置和页面 URL 中：

```text
docs/guide/index.mdx
     └─ frontmatter: section: guide
meta/site.json
     └─ sections[].id: guide
meta/sidebars.json
     └─ sidebars[].section: guide
```

这些位置必须一致。`navigation[].url` 通常指向 `/guide`，侧边栏中的每个 `url` 则
必须对应一个真实 MDX 页面。侧边栏数组顺序还决定页底“下一篇”的顺序。

<Infobox title="新增页面与新增章节不同" variant="warning">

在已有章节中增加页面，只需创建 MDX 并加入侧边栏；增加新的大章节，才需要同时修改
`sections`、`navigation`、侧边栏和文档目录。

</Infobox>

## 完整配置示例 {id="example"}

先在 `meta/site.json` 的 `sections` 数组末尾加入：

```json
{ "id": "guide", "title": "产品指南", "theme": "green" }
```

再在同一文件的 `navigation` 数组末尾加入：

```json
{ "text": "产品指南", "url": "/guide" }
```

最后在 `meta/sidebars.json` 的最外层数组末尾加入完整侧边栏对象：

```json
{
  "section": "guide",
  "items": [
    {
      "label": "开始使用",
      "items": [{ "text": "指南概览", "url": "/guide" }]
    }
  ]
}
```

注意前一个数组元素后要有逗号。完成后，原有“模板入门、编写文档、发布上线”仍可访问
，右上角会多出“产品指南”，但 `/guide` 页面尚未创建。

## 创建入口页面 {id="documents"}

创建 `docs/guide/index.mdx`：

```mdx
---
title: 指南概览
teaser: 从安装到第一个 Acme SDK 请求
section: guide
menu:
  - ['下一步', 'next']
---

这里介绍指南覆盖的内容和适用读者。

## 下一步 {id="next"}

继续阅读安装说明。
```

保存后，顶部“产品指南”打开 `/guide`，左侧显示“开始使用 → 指南概览”。如果只写配置
而不创建这个文件，测试会明确报告侧边栏 URL 找不到页面。

后续新增“API”等大章节时，重复同样的四步：增加 section、增加顶部入口、增加侧边栏
对象、创建入口 MDX。不要一次删除模板手册；确认自己的页面已经覆盖所需说明后，再同
时删除对应 `docs/` 目录、`sections`、`navigation` 和侧边栏对象。

## 验证结果 {id="verify"}

在仓库根目录运行：

```bash
npm test -- --runInBand
npm run build
```

预期结果：

- 测试不报告 section、frontmatter、sidebar URL 或 menu 锚点错误。
- 构建生成 `/guide` 静态页面。
- 右上角新增“产品指南”，原有模板手册入口仍然可用。
- 打开“产品指南”时使用绿色主题，左侧只显示该章节的小页面。

配置结构完成后，继续 [外观定制](/getting-started/appearance)，同步修改首页和
manifest。
