按下面的步骤，可以在几分钟内跑起一个可编辑的文档站。

## 环境要求 {id="requirements"}

- Node.js 24（仓库提供 `.nvmrc`，可用 `nvm use` 切换）
- Git
- npm（随 Node.js 安装）

先确认版本：

```bash
node --version
npm --version
git --version
```

预期 `node --version` 以 `v24.` 开头，其余两个命令能输出版本号。如果没有 `nvm`，
也可以直接安装与 `.nvmrc` 一致的 Node.js 版本。

## 从模板创建仓库 {id="create"}

1. 打开模板仓库，点击右上角 **Use this template → Create a new repository**。
2. 选择仓库所有者和名称；若准备使用 GitHub Pages，仓库可以是公开仓库。
3. 创建完成后，复制新仓库的 Git 地址。

如果 GitHub 页面没有 **Use this template**，说明源仓库尚未启用 Template
repository。你仍可以 fork，或下载代码后推送到一个空仓库。

<Aside title="Example">

```bash
git clone https://github.com/your-org/your-docs.git
cd your-docs
```

</Aside>

## 在本地启动 {id="local"}

进入仓库后安装依赖并启动开发服务器：

<Aside title="Example">

```bash
nvm use
npm install
npm run dev
```

</Aside>

终端出现 ready 提示后，打开 [`http://localhost:3000`](http://localhost:3000)。你
应该看到模板首页，并能从右上角进入“入门”“编写”“发布”三个大章节。

另开一个终端运行：

```bash
npm test -- --runInBand
```

看到全部测试通过，说明文档、配置和导航在修改前是一致的。后续每完成一个章节，都用
同一命令检查一次。

开发服务器适合日常写文档。它不会生成 Pagefind 搜索索引；需要验证搜索时，使用
[本地搜索](/publishing) 中的预览命令。

## 第一次定制 {id="customize"}

按这个顺序替换示例内容，最不容易遗漏：

1. 先按下一页的例子新增一个 `guide` 大章节和入口页面。
2. 修改 `meta/site.json` 中的标题、组织、仓库、顶部导航和页脚。
3. 同步修改 `public/manifest.webmanifest` 和 `pages/index.tsx`。
4. 逐页迁移自己的内容；每新增一页就立即加入对应侧边栏。
5. 内容完整后，再一起删除不需要的模板文档与导航。

<Infobox title="不要只改文件名" variant="warning">

重命名或删除 MDX 文件时，也要同步修改 `meta/sidebars.json`。新增大章节时，还要修
改 `meta/site.json` 的 `sections` 和 `navigation`。

</Infobox>

## 完成标准 {id="done"}

首次定制完成后，至少检查：

- 首页和浏览器标题不再显示模板占位内容。
- 顶部每个大章节都能打开，左侧每个链接都有效。
- 直接刷新任意文档 URL 不会得到 404。
- `npm test -- --runInBand` 和 `npm run build` 都成功。
- `npm run preview:search` 中能搜索到自己的页面标题和正文。

详细字段说明见 [站点配置](/getting-started/site-configuration)；文档组织方式见
[添加与组织文档](/writing)。
