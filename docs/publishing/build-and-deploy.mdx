模板输出的是静态站点。只要 `out/` 构建成功，就可以部署到支持静态文件的平台。

## 发布前检查 {id="checks"}

建议按顺序执行：

<Aside title="Example">

```bash
npm test -- --runInBand
npm run lint
npm run build
```

</Aside>

- `npm test`：验证文档结构、配置和关键约束。
- `npm run lint`：检查 TypeScript / React 代码。
- `npm run build`：导出静态站点并生成搜索索引。

## 生产构建 {id="build"}

```bash
npm run build
```

该命令会：

1. 执行 Next.js 构建与静态导出
2. 生成 sitemap
3. 用 Pagefind 为 `out/` 建立搜索索引

部署目录始终是仓库根目录下的 `out/`。

## 部署到 GitHub Pages {id="github-pages"}

模板已包含 `.github/workflows/deploy-pages.yml`，不需要复制额外的工作流。
它会在每次推送到 `main` 后构建站点、上传 `out/`，再发布到 GitHub Pages。

首次部署按下面的顺序设置：

1. 在 GitHub 创建仓库并将模板代码推送到 `main`
2. 打开仓库的 **Settings → Pages**
3. 在 **Build and deployment** 下将 **Source** 选择为 **GitHub Actions**
4. 再次推送到 `main`，或在 **Actions** 页面手动运行 **Deploy GitHub Pages**
5. 等待 `deploy` job 完成，从工作流页面或 **Settings → Pages** 打开站点

<Aside title="Example">

普通仓库 `docs-template` 的地址是：

```text
https://<用户名>.github.io/<仓库名>/
```

如果仓库名本身是 `<用户名>.github.io`，站点位于根地址：

```text
https://<用户名>.github.io/
```

</Aside>

工作流通过 `actions/configure-pages` 读取当前仓库的真实部署信息，并在构建时注入：

- `NEXT_PUBLIC_BASE_PATH`：普通仓库自动得到 `/<仓库名>`，根站点得到空路径
- `SITE_URL`：用于生成带有正确公开地址的 sitemap

因此无需手工填写仓库子路径。Next.js 静态资源、PWA manifest 和 Pagefind
搜索结果都会使用同一前缀。若默认分支不是 `main`，只需修改工作流中的
`on.push.branches`。

## 部署到 Vercel {id="vercel"}

仓库已包含 `vercel.json`：

```json
{
  "buildCommand": "npm run build",
  "outputDirectory": "out",
  "cleanUrls": true
}
```

将仓库导入 Vercel 后，直接使用默认构建设置即可。`cleanUrls` 会让
`/getting-started` 这类路径无需显式 `.html`。

## 部署到静态托管 {id="static"}

任意静态托管都可以：

1. 运行 `npm run build`
2. 上传或同步整个 `out/` 目录
3. 将站点根目录指向 `out/`

常见选择包括 Cloudflare Pages、Netlify 或对象存储 + CDN。

## Sitemap 域名 {id="sitemap"}

构建时可通过环境变量指定站点域名：

<Aside title="Example">

```bash
SITE_URL=https://example.com npm run build
```

</Aside>

未设置时，构建会回退到 Vercel 提供的域名变量，或本地默认值
`http://localhost:3000`。公开站点建议始终显式设置 `SITE_URL`。
