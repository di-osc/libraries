上一页介绍了 MDX 组件，本页继续使用标准 Markdown。图片和下载文件放在 `public/`，
文档中使用从站点根目录开始的 URL。示例资源已经包含在模板中，可以直接查看效果。

## 静态资源目录 {id="public"}

`public/` 是静态资源根目录：构建时其中的文件会原样复制到 `out/`，公开 URL 不包含
`public` 这一层。

示例目录：

```text
public/
├── images/
│   └── example-diagram.svg
└── manifest.webmanifest
```

因此：

```text
public/images/example-diagram.svg → /images/example-diagram.svg
public/manifest.webmanifest       → /manifest.webmanifest
```

预期结果是左边的文件路径在源码中存在，右边的 URL 能在开发服务器和静态站点中访问
。文件名建议使用小写英文、数字和连字符，避免空格和大小写混用。

## 插入图片 {id="images"}

标准 Markdown 图片由替代文本和资源 URL 组成：

源码：

```md
![MDX 文档经过 Next.js 构建成为可搜索静态站点](/images/example-diagram.svg)
```

实际效果：

![MDX 文档经过 Next.js 构建成为可搜索静态站点](/images/example-diagram.svg)

替代文本应描述图片传达的信息，而不是只写“图片”。装饰性图片可以使用空替代文本
`![](...)`。截图优先使用 WebP 或 PNG，图标和流程图优先使用 SVG。

<Infobox title="资源应随仓库保存">

外部 HTTPS 图片也能显示，但重要文档资源建议放入 `public/`，避免第三方地址失效或
阻止跨站加载。

</Infobox>

## 编写链接 {id="links"}

链接分为站内页面、当前页锚点、外部页面和下载文件：

```md
[返回模板概览](/getting-started) [跳到检查清单](#checklist)
[访问 GitHub](https://github.com/)
[查看 Web App manifest](/manifest.webmanifest)
```

实际效果：

- [返回模板概览](/getting-started)
- [跳到检查清单](#checklist)
- [访问 GitHub](https://github.com/)
- [查看 Web App manifest](/manifest.webmanifest)

站内链接从 `/` 开始，不写 `.mdx` 或 `.html`；当前页锚点必须对应标题中的显式
`{id="..."}`。外部链接写完整 HTTPS URL。不要把本地文件路径
`../docs/guide/installation.mdx` 当成公开链接。

## GitHub Pages 子路径 {id="base-path"}

普通 GitHub Pages 仓库会部署到 `/<仓库名>/`。文档源码仍统一写：

```md
![流程图](/images/example-diagram.svg)
```

当构建变量为 `NEXT_PUBLIC_BASE_PATH=/libraries` 时，模板输出：

```text
/libraries/images/example-diagram.svg
```

外链、`data:` URL、相对路径和已经带部署前缀的 URL 不会被重复修改。内置 GitHub
Actions 会自动设置这个变量；其他子路径托管环境可这样验证：

```bash
NEXT_PUBLIC_BASE_PATH=/docs \
SITE_URL=https://example.com/docs \
npm run build
```

构建成功后，在 `out/writing/assets.html` 中应能看到带 `/docs/images/` 前缀的图片
地址。

## 检查清单 {id="checklist"}

提交资源前逐项确认：

- 开发环境和生产构建都能显示图片。
- 图片替代文本能独立说明信息，尺寸不会撑破正文。
- 站内链接没有 `.mdx` 或 `.html` 后缀。
- 外部链接使用 HTTPS，下载文件真实存在于 `public/`。
- 子路径构建后，图片、manifest 和搜索资源使用同一个前缀。
