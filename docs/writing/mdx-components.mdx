模板把常用写作组件注册到了 MDX 运行时。在 `docs/**/*.mdx` 中可以直接写组件标签，
不需要 `import`。本页每个组件都先给出可复制源码，再紧跟页面中的实际效果。

## 使用方式 {id="principles"}

MDX 是 Markdown 与 JSX 的组合：普通段落、列表、表格继续使用 Markdown，需要提示框
、折叠区或多列布局时再使用组件。

```mdx
普通 Markdown 段落。

<Infobox title="提示">

组件内部仍然可以写 **Markdown**。

</Infobox>
```

组件开始标签、正文和结束标签之间保留空行，这样内部 Markdown 才会被正确解析。布尔
属性可以简写，例如 `spaced` 等价于 `spaced={true}`。

## Infobox {id="infobox"}

`Infobox` 用于从正文中突出提示、警告或危险操作。普通补充信息使用默认样式，需要用
户格外注意时才使用 `warning` 或 `danger`。

源码：

```mdx
<Infobox title="配置提示" emoji="💡">

修改导航后运行测试，确认每个链接都有对应页面。

</Infobox>

<Infobox title="删除前确认" variant="danger">

删除公开页面前先处理旧 URL，避免已有链接失效。

</Infobox>
```

实际效果：

<Infobox title="配置提示" emoji="💡">

修改导航后运行测试，确认每个链接都有对应页面。

</Infobox>

<Infobox title="删除前确认" variant="danger">

删除公开页面前先处理旧 URL，避免已有链接失效。

</Infobox>

| 属性      | 类型 / 可选值                    | 默认值    | 说明                   |
| --------- | -------------------------------- | --------- | ---------------------- |
| `title`   | 文本或节点                       | 无        | 提示标题               |
| `variant` | `default` / `warning` / `danger` | `default` | 语义和视觉样式         |
| `emoji`   | 字符串                           | 无        | 标题前的自定义图标     |
| `id`      | 字符串                           | 无        | 允许通过 hash 直接定位 |
| `list`    | 布尔值                           | `false`   | 适合列表内容的紧凑样式 |

## Button {id="button"}

`Button` 用于突出明确的下一步。段落中的普通引用仍应使用 Markdown 链接，避免每个
链接都变成高强调按钮。

源码：

```mdx
<Button to="/getting-started/quickstart" variant="primary">
  开始使用
</Button>
```

实际效果：

<Button to="/getting-started/quickstart" variant="primary">
  开始使用
</Button>

| 属性      | 类型 / 可选值                        | 默认值      | 说明               |
| --------- | ------------------------------------ | ----------- | ------------------ |
| `to`      | 字符串                               | 无          | 站内或外部目标 URL |
| `variant` | `primary` / `secondary` / `tertiary` | `secondary` | 按钮强调级别       |
| `large`   | 布尔值                               | `false`     | 使用大尺寸         |
| `icon`    | 内置图标名                           | 无          | 在文字前显示图标   |

## Accordion {id="accordion"}

`Accordion` 用于折叠可选细节、长配置或兼容性说明。完成任务必需的步骤不要折叠，否
则读者容易遗漏。

源码：

```mdx
<Accordion title="查看完整配置" id="full-config" expanded={false} spaced>

这里放不影响主流程的完整配置。

</Accordion>
```

实际效果：

<Accordion title="查看完整配置" id="full-config" expanded={false} spaced>

这里放不影响主流程的完整配置。

</Accordion>

| 属性       | 类型   | 默认值  | 说明               |
| ---------- | ------ | ------- | ------------------ |
| `title`    | 字符串 | 无      | 折叠标题           |
| `id`       | 字符串 | 无      | 可分享的锚点       |
| `expanded` | 布尔值 | `false` | 首次加载时是否展开 |
| `spaced`   | 布尔值 | `false` | 增加上下留白       |

## Grid {id="grid"}

`Grid` 把同级入口排成多列，在窄屏中自动换行。它只负责布局，内部通常放 `Button`、
卡片或短内容。

源码：

```mdx
<Grid cols={2}>
  <Button to="/getting-started">模板概览</Button>
  <Button to="/publishing">本地搜索</Button>
</Grid>
```

实际效果：

<Grid cols={2}>
  <Button to="/getting-started">模板概览</Button>
  <Button to="/publishing">本地搜索</Button>
</Grid>

| 属性           | 类型                  | 默认值  | 说明             |
| -------------- | --------------------- | ------- | ---------------- |
| `cols`         | `1` / `2` / `3` / `4` | `1`     | 宽屏列数         |
| `narrow`       | 布尔值                | `false` | 使用较窄内容宽度 |
| `gutterBottom` | 布尔值                | `true`  | 保留底部间距     |

## Aside {id="aside"}

`Aside` 用于把与当前小节直接相关的短示例放到右侧。宽屏中它位于正文右边，窄屏中自
动回到正文流。长教程和关键步骤仍应放在正文。

源码：

````mdx
<Aside title="Example">

```bash
npm install
npm run dev
```

</Aside>
````

实际效果：

<Aside title="Example">

```bash
npm install
npm run dev
```

</Aside>

`Aside` 必须写在相关 `##` 小节内部，否则它与正文的垂直位置可能不匹配。

## Tag {id="tag"}

`Tag` 用于显示短状态、版本或分类，不适合承载完整句子。

源码：

```mdx
当前版本 <Tag variant="new" tooltip="首次提供本地搜索">1.0</Tag>
```

实际效果：

当前版本 <Tag variant="new" tooltip="首次提供本地搜索">1.0</Tag>

| 属性      | 类型 / 可选值   | 默认值  | 说明               |
| --------- | --------------- | ------- | ------------------ |
| `variant` | `new` / `model` | 无      | 版本或模型标签样式 |
| `tooltip` | 字符串          | 无      | 悬停或聚焦时的说明 |
| `spaced`  | 布尔值          | `false` | 增加左右间距       |

## 类型标注 {id="type-annotations"}

双波浪线语法会渲染成行内类型标注，而不是删除线。类型名称存在于
`meta/type-annotations.json` 时，还会自动链接到对应参考页面。

源码：

```md
`createClient()` 返回 ~~AcmeClient~~。
```

实际效果：

`createClient()` 返回 ~~AcmeClient~~。

对应映射：

```json
{
  "AcmeClient": "/writing/mdx-components#type-annotations"
}
```

没有映射的类型仍会显示为类型样式，只是不带链接。普通删除内容不要使用双波浪线，以
免被误认为类型标注。

## Markdown 能力 {id="markdown"}

普通 Markdown 会自动使用模板样式，包括表格、列表、引用、图片、链接、代码块和标题
锚点。代码块应标注语言，例如：

```python
client = create_client()
```

页面效果就是上方已经渲染的 Python 代码块。图片和链接的完整示例见
[图片与链接](/writing/assets)，下一章会继续沿用这里的写法。
