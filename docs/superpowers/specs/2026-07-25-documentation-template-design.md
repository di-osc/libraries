# 文档站模板化设计

## 背景

当前仓库是 `di-osc` 的库文档中心，包含 `asr-data` 和 `vad-burn` 的项目文档、
导航、首页入口及静态资源。这些文档已经迁移到各自项目，因此本仓库将改造成一个
可复用的中文文档站模板。

模板仓库本身既是可运行的文档站，也是模板的使用手册。最终站点不保留任何产品
示例文档。

## 目标

- 删除现有项目专属文档、路由、链接、文案和资源。
- 保留 MDX 文档、静态导出、Pagefind 本地搜索和现有通用组件。
- 将站点身份、导航和文档组织集中在配置文件中。
- 使用 spaCy 风格的顶部大章节、左侧小页面、中央正文和右侧 Example 布局。
- 提供完整的中文模板使用手册。
- 让使用者复制仓库后，主要通过修改配置和 MDX 文档完成自己的文档站。

## 非目标

- 不提供中英文双语内容。
- 不保留产品示例文档。
- 不增加交互式脚手架或初始化命令。
- 不进行与模板化无关的 UI 或组件重构。

## 最终信息架构

站点只保留模板使用手册内容，但将手册拆成三个真实大章节。大章节显示在桌面端顶部
导航右侧，每个大章节的页面显示在左侧：

- 入门（`/getting-started`）
  - 模板概览（`/getting-started`）
  - 快速开始（`/getting-started/quickstart`）
  - 站点配置（`/getting-started/site-configuration`）
- 编写（`/writing`）
  - 添加与组织文档（`/writing`）
  - MDX 组件（`/writing/mdx-components`）
- 发布（`/publishing`）
  - 本地搜索（`/publishing`）
  - 构建与部署（`/publishing/build-and-deploy`）

当前页面的 `menu` 小节继续嵌套显示在左侧活动页面下。原 `/guide/*` 路由直接替换，
不保留兼容路由。

首页改为通用文档站模板介绍，并提供进入使用手册的主要入口。

## 页面布局

桌面端沿用仓库基于 spaCy 的文档布局语言：

- 白底固定顶部导航，站点身份位于左侧，大章节位于右侧。
- 左侧固定侧边栏只显示当前大章节的页面和当前页小节。
- 中间是正文，保留宽阔留白、大标题和主题色强调。
- 右侧 Example 与对应正文小节并排，不使用固定的整页示例栏。

移动端将导航折叠为选择器，Example 回到相关正文下方，避免缩窄正文或影响命令复制。
模板只复用布局语言，不复制 spaCy 品牌、Logo 或具体文档内容。

## Example 能力

MDX 运行时正式注册 `Aside`，供文档作者显式编写右侧示例：

````mdx
<Aside title="Example">

```bash
npm install
npm run dev
```

</Aside>
````

桌面端沿用现有深色悬浮卡片样式。现有 `Aside` 高度计算负责在示例高于正文小节时扩展
小节，避免相邻示例重叠。快速开始、站点配置、文档组织、MDX 组件、搜索和部署页面
都实际使用 Example；MDX 组件页同时说明这种写法。

## 配置边界

使用者主要接触以下位置：

- `meta/site.json`：配置站点名称、说明、域名、组织、仓库、顶部导航和页脚。
- `meta/sidebars.json`：配置文档分区、分组、页面名称和页面顺序。
- `docs/`：新增或编辑 MDX 文档。
- `pages/index.tsx`：按需修改首页文案和入口卡片。
- `meta/type-annotations.json`：仅在需要类型链接功能时配置。

模板手册会明确说明每个位置的用途、必要字段和修改方式。

## 清理范围

- 删除 `docs/asr-data/` 和 `docs/vad-burn/`。
- 删除 `public/asr-data/` 中的项目专属图片。
- 删除 `asr-data`、`vad-burn` 及 `di-osc` 的项目专属路由、文案和链接。
- 将 `package.json` 的包名改成通用模板名称。
- 检查并清理 sitemap、Vercel、PWA manifest、SEO 和其他配置中的旧域名或品牌。
- 保留通用组件、字体、图标、样式和搜索实现。
- 保留 spaCy 来源说明以及仓库现有许可证中的上游归属。

## 模板手册内容

手册覆盖一条完整的使用路径：

1. 复制模板并安装依赖。
2. 修改站点基础配置。
3. 创建 MDX 页面并加入侧边栏。
4. 使用模板内置的 MDX 组件。
5. 运行开发服务器进行日常预览。
6. 使用 `npm run preview:search` 构建并验证 Pagefind 搜索。
7. 执行生产构建并部署到 Vercel 或其他静态托管平台。

手册本身使用模板的实际 MDX、导航和组件能力，因此也承担可运行示范的作用，但不
引入虚构产品或产品文档。

## 搜索与构建

保留当前 Pagefind 搜索流程：

- 日常编辑使用 `npm run dev`，该模式不生成搜索索引。
- 搜索验证使用 `npm run preview:search`。
- 生产构建使用 `npm run build`，依次完成静态导出和 Pagefind 索引。
- 搜索索引覆盖页面标题、章节标题和正文，并继续排除代码块及页面框架内容。

## 实施顺序

实施基于最新获取的 `origin/main`。模板基础改造完成后，依次完成：

1. 将单一 `/guide` 分区拆成入门、编写和发布三个大章节。
2. 注册 `Aside` MDX 组件并补充渲染测试。
3. 在模板手册中加入与正文对应的 Example。
4. 改写首页，使其突出配置驱动、MDX + Example 和本地搜索/静态部署。
5. 扫描旧路由和残留内容。
6. 执行测试、代码检查、生产构建、搜索和真实页面验证。

## 验收标准

- 面向最终模板的运行时内容、配置和公开说明不再包含旧项目名称、旧项目链接和专属
  资源；本设计说明中的迁移背景不计入该项。
- 首页、导航、侧边栏、页脚及全部手册页面可正常访问。
- 顶部显示入门、编写、发布三个大章节，左侧只显示当前大章节的小页面。
- 当前页面的小节导航正确嵌套在左侧活动页面下。
- 桌面端 Example 显示在相关正文右侧，移动端回到正文流内。
- 文档内部链接与“下一篇”顺序正确。
- `npm test -- --runInBand` 通过。
- `npm run lint` 通过。
- `npm run build` 成功完成静态导出和 Pagefind 索引。
- 搜索能够检索模板手册标题、章节和正文，但不索引代码块。
